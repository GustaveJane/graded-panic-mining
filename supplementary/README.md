# Supplementary material

This directory holds the artefacts that the manuscript promises to release. Each
entry below is tied to the sentence in the paper that promises it, so a reader (or
a reviewer) can check the promise against the file.

| Paper statement | Where it is said | File |
|---|---|---|

| Full codebook, with decision boundaries between adjacent codes and worked examples | Appendix M | `codebook/codebook_L1_L2_L3.md` |
| Original annotation prompt template and the ten additional worked examples | Appendix (Table 30 note) | `prompts/panic_annotation_prompt_zh.py.txt`, `prompts/few_shot_examples.tsv` |
| Event-sensitivity daily data | Data and Code Availability | `tables/daily_covid_panic_2019_2020.csv` |
| Event-response table | Data and Code Availability | `tables/event_response_table.csv` |
| GMM stratification result tables | Data and Code Availability | `tables/gmm_thresholds.csv`, `tables/gmm_diagnostics.csv` |
| Stratified five-window user panel (de-identified) | Data and Code Availability | `panel/user_tier_panel_5windows.csv.gz`, `panel/README.md` |
| Analysis scripts and plotting code | Data and Code Availability | `../src/` (see `../docs/reproduction.md`) |

Everything here is generated by `../tools/build_supplementary.py`, which reads the
project's own sources. Nothing in this directory was typed in by hand.

Two build inputs are deliberately **not** in this repository: the manuscript's LaTeX
sources (`*.tex` is excluded so that the paper itself is not published) and the
licensed corpus. The builder parses the lexicon appendix out of the paper's LaTeX
file and the prompt out of `../src/data/filter_covid.py`; if the LaTeX file is absent
it will fail at the lexicon step. The committed `lexicon.tsv` is the output, so
readers do not need to run the builder — it exists so the release can be audited and
regenerated by the authors.

## Notes on individual files

### `lexicon/lexicon.tsv`

One row per surface form: `surface_form`, `dimension_en`, `dimension_zh`, `kind`
(`evaluative` / `structural`), `scored` (1 = enters an appraisal score, 0 = descriptive
covariate), `group_n` (declared size of the group) and `also_in` (set when a form is
listed under two groups).

Counts: **163 evaluative terms** across the five appraisal dimensions plus
**28 distinct structural features**, giving **191 unique surface forms**.

Two caveats worth knowing before quoting a number:

- The LaTeX appendix caption counts *30* structural features and *163* evaluative
  terms. Those add to 193, but two forms (`是不是`, `有没有`) appear in both the
  uncertainty list and the interrogative list, so the number of **unique** forms is
  191. The paper's body text says "191 unique surface forms", which is correct; the
  caption's "163 + 30" breakdown silently double-counts those two. Either reword the
  caption to "163 evaluative terms and 30 structural slots (191 unique forms)" or
  drop the two duplicates from one of the lists.
- Body text also says the 191 forms sit "across five appraisal dimensions". Strictly,
  28 of them are structural covariates that enter no appraisal score, as the caption
  itself states. Recommend "…163 evaluative terms across five appraisal dimensions,
  together with 28 structural features".

### `tables/daily_covid_panic_2019_2020.csv`

Daily aggregate series: `total_posts`, `covid_posts`, `panic_posts`,
`overall_panic_score`, `panic_rate` (panic posts / COVID-related posts) and 7-day
moving averages.

**Coverage is 2019-12-01 to 2020-06-30 (213 days), not the full calendar year.** The
RDD and event analyses in the paper use this window; the unified daily series ends at
2020-06-30. The file name advertised in the paper ("…2019 2020") therefore oversells
the range — rename it in the manuscript to `daily_covid_panic_2019-12_to_2020-06.csv`,
or extend the series before claiming a full year.

### `tables/event_response_table.csv`

The eleven anchor events of Table 21, **recomputed** from the daily series with the
recipe stated in that table's note (baseline = mean daily panic rate over the 30 days
ending 3 days before the event; response = mean over the 3-day window from the event;
only days with >= 500 COVID-related posts are eligible). The paper's published values
are carried alongside as `paper_*` columns for audit.

Agreement: maximum absolute difference in Δ is **0.06 pp** across the ten events with
an eligible baseline. E11 (Xinfadi) reproduces exactly (baseline 0.65%, Δ +1.71 pp);
z = 11.71 here vs 11.74 in the paper, the difference being the sample-vs-population
standard deviation in the denominator. E1 has no eligible baseline (the corpus starts
on 2019-12-01), which is why the paper reports it as NA.

### `prompts/`

`panic_annotation_prompt_zh.py.txt` is lifted verbatim out of
`../src/data/filter_covid.py`: three template variants (`keyword`, `fewshot`,
`example`) plus the shared system message. `fewshot` is the deployed one and carries
the 12 examples reproduced in Table 30; `example` carries the 10 further worked
examples with full reasoning that the paper promises.

`few_shot_examples.tsv` puts all 22 examples in one table (`source`, `text`, `label`,
`rationale`). The text is Chinese, as deployed; Table 30 gives the English gloss.

### `preprocessing/preprocessing_rules.md`

Inventories the preprocessing rules that are **actually implemented in this
repository**, extracted from the source files.

One promise is not yet honoured: the manuscript says "the complete rule lists are
released with the replication code" for deduplication, ad/bot removal and text
normalisation. Those three steps ran on the compute server, and that script is not in
this repository. Either recover it, or soften the sentence to name only the rules that
are released here.

## Not released

- **Raw posts or any free text at user level.** Excluded by design: the corpus is
  governed by the Weibo-COV 2.0 terms of use.
- **Corpus-level deduplication and account-filtering rules.** That stage produced the
  monthly `cleaned_YYYY-MM.csv` files in an earlier compute environment and its rule
  list could not be recovered, so it is specified in prose in the manuscript rather
  than shipped as code. The rules for the stages that are implemented here are in
  `preprocessing/preprocessing_rules.md`.
